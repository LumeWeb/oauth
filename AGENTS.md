# AGENTS.md

This file provides development guidelines and architectural documentation for
the OAuth library.

## Project

Shared OAuth 2.1 authorization server domain logic (`go.lumeweb.com/oauth`).
It is a **domain-logic + storage** layer: it prescribes no HTTP, middleware,
authentication strategy, or framework integration. The HTTP layer stays in
each consumer.

## Root package scope (stdlib only)

- `oauth.go` — core types (`Config`, `Client`, `AuthorizationCode`,
  `RefreshToken`, `AccessToken`, `TokenResponse`, ...), `AuthorizationServer`
- `storage.go` — `Storage` persistence interface
- `pkce.go` — `VerifyPKCE`, `ValidBase64URL` (RFC 7636)
- `tokens.go` — `NewToken`, `NewTokenPair` (opaque tokens)
- `redirect.go` — `MatchRedirectURI`, `IsLoopbackRedirectURI`,
  `AllowedClientRedirect` (RFC 8252 §7.3)
- `refresh.go` — `RotateStatus` + rotation domain types (RFC 9700)
- `metadata.go` — `BuildASMetadata`, `BuildProtectedResourceMetadata`
  (RFC 8414 + RFC 9728)
- `errors.go` — typed OAuth errors (RFC 6749 §5.2)

Sub-packages may add dependencies:

- `storage/gorm` — `gorm.io/gorm` only (default production adapter)
- `storage/memory` — stdlib only (tests / dev)

The root package must never import the GORM dependency; that lives only in
`storage/gorm`.

## Common Commands

### Building

```bash
go build -v ./...
```

### Testing

```bash
go test -v -race -coverprofile=coverage.out -covermode=atomic ./...
go tool cover -func=coverage.out
```

### Code Generation

```bash
# Generate mocks for the Storage interface into ./mocks
mockery
```

### Dependency Management

```bash
go mod tidy
go mod verify
```

## Conventions

- Follow the standard Go library layout: one package per directory.
- The root package is stdlib-only; keep `gorm` imports out of it.
- Exported GORM model structs live in `storage/gorm/models.go` so consumers
  can reference their GORM tags when writing their own migration SQL.
- Do not ship or manage migrations in this library — consumers own their
  own goose SQL.
- Documentation: godoc on all exported symbols; comment the *why*, not the
  *what*.

## Release

Releases are driven by [Knope](https://knope.tech/) (`knope.toml`) and the
`.github/workflows/release.yml` workflow. `go.mod` is the versioned file.
`CHANGELOG.md` is generated by Knope — never edit it by hand.
